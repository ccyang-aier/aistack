# Codex 增量迁移指南

这份指南给后续本机 AI 使用：当当前机器新增了可迁移插件或 skill，需要把它追加到 `C:\AIWorks\26Coding\aistack\codex` 迁移包时，按这里执行。

## 原则

1. 只读当前机器源目录，只向迁移包目录写入。
2. 不修改当前机器 `C:\Users\17335\.codex` 的配置、登录、插件启用状态或缓存状态。
3. 不复制 `auth.json`、OAuth token、connector 授权状态、日志、sqlite 状态库、历史线程、本机权限状态。
4. 插件必须先分类，再决定是否纳入。

## 分类规则

| 类别 | 是否纳入本包 | 判断方式 |
|---|---|---|
| 纯 skill | 纳入 | 目录内有 `SKILL.md`，不依赖 connector/app 授权。 |
| Skill-only 插件 | 纳入 | `.codex-plugin/plugin.json` 有 `skills`，无 `apps`，无强本机权限依赖。 |
| Skills + 本地 MCP 插件 | 纳入或条件纳入 | 有 `mcpServers`，但 MCP 可通过本地命令、Node/npm、Python 或远程 proxy 重建。 |
| Primary runtime 插件 | 纳入 | 如 `documents/presentations/spreadsheets`，同时确认 runtime 包已复制。 |
| App connector 插件 | 不纳入 | `.codex-plugin/plugin.json` 或 `.app.json` 指向 `connector_*` / `asdk_app_*`。 |
| 本机能力型插件 | 不纳入 | Browser、Chrome、Computer Use，或依赖本机 native host / OS 权限。 |

## 快速识别插件结构

在当前机器运行：

```powershell
Get-ChildItem -Recurse -Force C:\Users\17335\.codex\plugins\cache -Filter plugin.json |
  ForEach-Object {
    $j = Get-Content -Encoding UTF8 $_.FullName | ConvertFrom-Json
    $props = @()
    foreach ($k in @("skills","mcpServers","apps","commands","hooks","resources")) {
      if ($j.PSObject.Properties.Name -contains $k) { $props += $k }
    }
    [pscustomobject]@{
      Name = $j.name
      Version = $j.version
      Contains = ($props -join ",")
      Path = $_.FullName
    }
  } | Format-Table -AutoSize
```

如果出现 `apps`，继续检查：

```powershell
Get-ChildItem -Recurse -Force <插件根目录> -Filter .app.json |
  ForEach-Object {
    Get-Content -Encoding UTF8 $_.FullName
  }
```

只要 `.app.json` 指向 `connector_*` 或 `asdk_app_*`，不要放入本迁移包，除非用户明确要求迁移外壳并用自建 MCP/proxy 替代。

## 增量添加一个 skill

假设源 skill 为：

```text
C:\Users\17335\.agents\skills\new-skill
```

复制到包内：

```powershell
Copy-Item -LiteralPath C:\Users\17335\.agents\skills\new-skill `
  -Destination C:\AIWorks\26Coding\aistack\codex\skills\agents\new-skill `
  -Recurse -Force
```

然后更新：

1. `迁移文件清单.md`：在“已打包用户级 skills”表中增加说明。
2. `scripts/validate-package.ps1`：把 `new-skill` 加入 `$RequiredAgentSkills`。

## 增量添加一个插件

假设源插件根目录为：

```text
C:\Users\17335\.codex\plugins\cache\openai-curated\new-plugin\<版本或hash>
```

复制到包内标准位置：

```powershell
Copy-Item -LiteralPath C:\Users\17335\.codex\plugins\cache\openai-curated\new-plugin\<版本或hash> `
  -Destination C:\AIWorks\26Coding\aistack\codex\plugins\new-plugin `
  -Recurse -Force
```

然后更新以下文件：

1. `package-manifest.json`：在 `plugins` 数组里增加 `new-plugin`。
2. `install.ps1`：在 `$PluginNames` 数组里增加 `new-plugin`。
3. `marketplace/marketplace.template.json`：增加 `new-plugin` 的 marketplace 条目。
4. `scripts/validate-package.ps1`：在 `$RequiredPlugins` 数组里增加 `new-plugin`。
5. `迁移文件清单.md`：在“已打包插件”表中增加版本、分类、能力说明和目标机可用条件。
6. `一键迁移指南.md`：如果新增插件需要 Node、Python、runtime、MCP 或远程 proxy，在“可用性说明”中补充。

## 增量添加 primary runtime 或额外使能包

如果新增插件依赖额外 runtime，不要只复制插件目录。必须把 runtime 或依赖包同步放入：

```text
C:\AIWorks\26Coding\aistack\codex\runtime
```

然后修改 `install.ps1`，在安装阶段复制该 runtime 到目标机约定位置。

当前 primary runtime 的目标位置是：

```text
%USERPROFILE%\.cache\codex-runtimes\codex-primary-runtime
```

## 增量完成后的自检

执行：

```powershell
powershell -ExecutionPolicy Bypass -File C:\AIWorks\26Coding\aistack\codex\scripts\validate-package.ps1
```

再检查包内插件 manifest：

```powershell
Get-ChildItem -Directory C:\AIWorks\26Coding\aistack\codex\plugins |
  ForEach-Object {
    $manifest = Join-Path $_.FullName ".codex-plugin\plugin.json"
    if (-not (Test-Path -LiteralPath $manifest)) {
      throw "Missing plugin manifest: $($_.Name)"
    }
  }
```

## 不要做的事

不要复制这些路径或文件：

```text
C:\Users\17335\.codex\auth.json
C:\Users\17335\.codex\.sandbox-secrets
C:\Users\17335\.codex\state_*.sqlite
C:\Users\17335\.codex\logs_*.sqlite
C:\Users\17335\.codex\installation_id
C:\Users\17335\.codex\browser
C:\Users\17335\.codex\computer-use
C:\Users\17335\.codex\chrome-native-hosts*.json
```

不要用 `robocopy /MIR` 或递归删除来刷新迁移包。需要更新时只覆盖指定新增或变更目录。
